# 演奏录音与乐谱偏差复盘台

本地 Web 应用：上传**单声部 MusicXML** 与 **WAV 录音**，自动展开反复记号、
提取基频与起音，用允许漏音 / 多音 / 局部速度变化的**单调动态规划**对齐，
把每个音符区分为**错音、漏音、多音、起音偏移、时值偏差**并标注置信度；
无声 / 多声部歧义片段进入**待确认**，绝不强配。可锁定或排除锚点后**增量重算**，
界面联动播放，一键导出含**原谱坐标、音频时间与判定依据**的**确定性 JSON**。

还支持**多次演奏对比**：从 2–6 次同曲录音的已完成复盘中指定基线，
系统按展开音符序列 + 原谱坐标生成**乐谱指纹**、拒绝不可比录音，
把每次已确认的对齐版本固化为**只读快照**，按谱音生成**版本矩阵**
（已解决 / 新出现 / 持续 / 不可比），可按小节筛选并在录音间同步定位。

在此之上提供**最佳片段合成轨**：只在对比**未过期**时，从各次录音中按
连续谱音区间挑出“已确认且置信度达标”的最佳片段，按公开的全局代价
（异常数 / 切换次数 / 切点两侧响度差与局部速度差）做动态规划选源，
切点严格落在已对齐起音边界、按基线局部节拍时间伸缩并短交叉淡化，
输出可试听、可下载的 WAV 与含原始时间段 / 变速比 / 代价依据的
**确定性清单**。可钉住或禁用某谱位的来源；任一谱位无合格来源时
**阻止重建并逐位给出原因，但绝不删除已固化的 WAV / 清单**——
对已 built 任务施加钉住/禁用只更新阻塞规划（status 仍为 built，
试听下载照常），解除阻塞后必须**显式重建**才原子替换。合成任务
固化对齐版本与音频哈希，来源变化**只标记过期**，必须显式重建。

最后提供**偏差练习处方与复测**：从已分析乐曲或**未过期**的多次演奏
对比中框选若干**连续谱段**，为每段声明必须消除的偏差类别（错音 / 漏音 /
多音 / 起音偏移 / 时值偏差）、允许的最大起音误差与时值比例误差、最多
异常音数，以及是否禁止待确认；创建时把**当前乐谱指纹、对齐版本与规则**
整体固化为**只读处方**。处方可关联后续**同曲**录音复测，复测准入分两条
**独立**校验：**来源固化成员任一过期**（对齐版本/音频哈希变化）时必须先
**显式重绑**；而**同曲新目标无需重绑**——只要目标已完成分析且拥有
**当次已确认对齐版本**即可复测，复测时当场固化该目标的对齐版本、音频哈希
与逐项结果及所依据的来源版本。谱指纹不同、或目标没有已确认对齐时一律
**拒绝**；系统按处方谱段重新计算确定性的**通过 / 未通过 / 不可判定**，
逐项给出实际值、阈值、证据音符与失败原因。历史复测只读，之后来源或目标
变化不改写旧结果。处方状态只能按 `created → retested → voided` 推进；
创建与复测均以 `request_id` **幂等**（重复提交原样回放首次响应，含 409）；
来源过期只能**显式重绑**且**保留全部旧复测结果**。界面提供处方时间线与
相邻复测的逐项差异对比。

在此之上提供**偏差片段练习谱**：在**单次复盘**中按展开后的**整小节与反复
轮次**框选若干**连续片段**，逐段设置**循环次数、起始速度与逐轮增速**。
每段必须包含**已确认的偏差音**；**待确认、已排除或低于置信阈值**的谱位会
逐位提示并**阻止生成**。系统从原 MusicXML 提取对应演奏轮次的**整小节**，
保留音高、时值、休止、拍号、调号与片段内连音，按选定顺序逐轮展开；
**跨片段连音在边界截断并逐处标记，绝不留下悬空连音**，每轮开头注明原谱
坐标与 BPM。下载的 MusicXML 内嵌**来源谱哈希、对齐版本与生成参数**；
来源变化**只把对应版本标记过期、全部历史稿仍可下载**。每次成功生成
（创建 / 显式重建通过校验）都分配**独立版本**（独立文件 + 固化清单 +
数据库指针，互不覆盖），任务始终指向明确的**当前版本**；可按练习谱查看
**版本历史并下载任一版本**。重建失败（逐位阻塞 / 生成出错）**不新增、
不改写任何版本**，已有过期稿仍可下载；删除任务清理全部版本。

最后提供**谱面修订迁移**：选择一条**已分析录音**及其当前 MusicXML，上传
一份**修订版单声部 MusicXML**。两侧都用 music21 展开反复后，按
**（原谱小节、反复轮次、拍位、音高、时值）**做确定性匹配——同谱位且同内容
为**保留**，同谱位改音高/时值为**修改**，同内容换谱位为**移动**（全局单调
序列对齐，移动代价 = 展开单位跨越 + 拍位距离，等代价配对即歧义），旧谱
独有为**删除**、新谱独有为**新增**，结构冲突谱位为**无法匹配**。基于匹配
结果生成**迁移预览**：把锚点、对齐快照、未过期对比、处方、练习谱片段逐项
标为**可继承 / 需复核 / 失效**并说明原因；**禁止静默改写历史**——旧录音、
旧对齐版本与全部产物只读，用户显式确认（`request_id` 幂等）后才创建新的
**谱面修订记录**与**供后续录音使用的复盘入口**，并预置可继承的排除锚点；
之后可向新入口上传后续录音，分析完成后把**可继承/需复核**的处方与练习谱
**一键接续**为全新对象（练习谱接续仍逐位准入，不通过返回 422 且不生成）。
**匹配冲突（谱位键重复/缺坐标/等代价移动）或多声部歧义必须阻止提交**；
预览后来源谱或对齐版本变化同样阻止。报告可导出**确定性 JSON**
（键排序、固定精度、无时间戳随机项）。

技术栈：Python 3.11 · FastAPI · SQLite · music21 · librosa；前端原生
JavaScript（无构建步骤，第五个标签页为谱面修订迁移）；Docker Compose
一键启动。

## 1. 一键启动

前置：安装 Docker 与 Docker Compose（`docker compose` 子命令）。

```bash
docker compose up --build          # 前台启动；加 -d 可后台运行
```

首次构建会安装 librosa / music21 等依赖（约 2–4 分钟）。容器内置
健康检查（`GET /api/health`），启动后浏览器访问：

> **http://localhost:8000**
> （合成轨在“多次演奏对比”页内向下滚动；偏差练习处方在第三个标签页；
> 偏差片段练习谱在第四个标签页；谱面修订迁移在第五个标签页，也可从单次
> 复盘页直接进入）

数据（上传文件、SQLite 数据库）持久化在宿主机 `./data` 目录。
停止：`Ctrl+C` 或 `docker compose down`；想彻底清空：`rm -rf data/`。

### 不用 Docker（本地开发）

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
DATA_DIR=./data DB_PATH=./data/review.db FRONTEND_DIR=../frontend \
    uvicorn app.main:app --reload --port 8000
```

### 生成示例素材

仓库自带含反复记号的 `backend/sample/sample_score.musicxml`，
以及只用标准库即可生成的"问题演出" WAV（错音 / 漏音 / 多音 / 起音晚 /
时值短 / 多声歧义 / 无声歧义）：

```bash
python3 backend/sample/make_sample_wav.py \
    -o backend/sample/sample_performance.wav
```

在页面上传这两个文件即可看到各类判定。

## 2. 使用流程

1. **上传**：填写标题，选择单声部 MusicXML 与 WAV。谱面同步解析
   （反复记号立即展开），音频在后台提取基频与起音，页面轮询进度。
2. **复盘视图**：三条共用同一时间轴的泳道——
   * **乐谱（展开）**：每个音符按*期望起音时间*摆放，颜色即判定结果，
     块上标注音名、原谱小节号（反复的第 2 次演奏带 `'2` 标记）；
   * **偏差轨道**：空心圆=期望起音，菱形位置→实际起音，横线长度为
     *起音偏移*；小框宽度表示实际时值，超阈用黄色描边；
   * **录音起音**：实际检测到的起音块（底层为波形包络），歧义片段显示
     `多声?` / `无声?`。
   配对音符之间有连线，锁定锚点为蓝色粗线。
3. **联动播放**：点击轨道空白处定位，`▶ 播放` 后白色播放头同步推进；
   点击任意谱块 / 观测块可查看详细判定依据（basis 字符串）。
4. **修正对齐（增量重算）**：
   * 选中一个乐谱音 + 一个稳定观测音 → **🔒 锁定配对**（锁之间互不影响，
     只有边界变化的片段会重算，顶部显示“命中 X / 重算 Y”）；
   * 选中单个音符 → **排除乐谱音 / 排除观测音**；
   * 锚点可在左下“锚点”面板删除，删除后同样增量重算。
5. **待确认片段（不强配）**：多声部歧义 / 有声起音但无稳定基频的观测
   进入左下面板，可选择“配对到指定乐谱音（锁定）/ 确认多音 / 忽略”。
   在用户处置前，这些观测不会与任何乐谱音自动配对。
6. **导出**：右上角“导出确定性 JSON”，文件名含当前对齐版本号。
   相同输入 + 相同锚点下，导出的 JSON **字节级一致**
   （键排序、固定精度、无时间戳随机项），可直接用于回归比对。

## 2b. 多次演奏对比

同页顶部切换 **“多次演奏对比”** 标签（访问路径仍是 `http://localhost:8000`，
纯前端切换；数据接口前缀 `/api/comparisons`）。

1. **新建**：左侧“③ 演奏对比 → ＋ 新建对比”，勾选 **2–6 次**已完成分析的
   录音，用单选圆点指定其中一次为**基线**。
   * 后端用每个谱音的 MIDI、展开 beat/dur_q 与原谱坐标
     （小节 / 拍 / 反复出现序号）计算 **sha256 乐谱指纹**；
     指纹不一致（非同曲、反复展开不同）会被整体拒绝并提示是哪几次，
     **不会混入不可比录音**。
2. **只读快照**：创建（或显式刷新）时，每个成员**当前已确认**的对齐版本
   被逐音固化到 `comparison_snapshots`（含谱音状态、标签、置信度与该录音内
   起音时间）。之后即使继续修改某次复盘的锚点 / 待确认处置，
   **对比结论保持不变**——对比卡片与列表出现橙色“过期”标记，
   必须由用户点击 **“显式刷新”** 才会以最新对齐重新固化，
   系统绝不静默改写结论。来源检测：对齐版本号变化、WAV/XML 哈希变化。
3. **版本矩阵判定（按谱音逐音，相对基线）**：

   | 基线 | 目标 | 判定 |
   |---|---|---|
   | 异常 | 正常 | `resolved` 已解决 |
   | 正常 | 异常 | `new` 新出现（= 相对基线回退） |
   | 异常 | 异常 | `persistent` 持续 |
   | 任一侧为下列任一情形 | — | `incomparable` 不可比 |

   “异常”= 错音 / 漏音（状态）或起音偏移 / 时值偏差（标签）。
   **不可比**的三种来源：该谱音位置存在未处置的**待确认**观测、
   用户**已排除**该谱音、或任一侧**置信度低于阈值**
   （复用 `CONF_MED = 0.50`，见 config `COMPARE_MIN_CONFIDENCE`）。
   待确认与低置信结果**既不算改善也不算回退**。
4. **筛选 / 定位 / 汇总**：
   * 工具栏“小节筛选”（反复小节按出现序号区分）同时过滤矩阵与区段；
   * 点击矩阵任一单元格，各录音按自己的对齐快照把该谱音映射回本录音时间，
     **同步定位**；“▶ 同时播放”可多轨对照；
   * 每张目标卡片给出已解决 / 新出现 / 持续 / 不可比 / 均正常计数、
     **相对基线的回退清单**（新出现的异常谱音与新多音），
     下方“仍异常问题区段”把连续的新出现 / 持续谱音合并成区段，
     点击区段同样同步定位。

## 2c. 最佳片段合成轨

入口：打开一次对比后，页面下方就是 **“最佳片段合成轨”** 面板
（访问路径仍是 `http://localhost:8000`，同页向下滚动即可；
数据接口前缀 `/api/synthesis`，创建接口挂在
`/api/comparisons/{id}/synthesis`）。

1. **前提：对比未过期**。任一成员的对齐版本或 WAV 变化，对比显示橙色
   “过期”，合成的创建 / 覆盖 / 重建都会被拒绝（409），必须先在对比页
   点 **“显式刷新”** 固化最新快照。
2. **规划（不产生音频）**：点 **＋ 创建最佳片段合成轨**。系统按基线
   展开谱位逐位检查各录音，只把满足下列条件的片段视为**合格来源**：
   * 已确认配对（自动 `match` 或锁定 / 强制锁定 `locked_match`）；
   * 无未处置待确认观测、非用户排除；
   * 置信度 ≥ `0.50`（`config.SYNTH_MIN_CONFIDENCE`）。

   错音 / 起音偏移 / 时值偏差仍然合格（否则可能整曲无解），但计入
   异常代价；漏音 / 多音 / 低置信 / 待确认直接不可选，选源表中灰显并在
   悬停提示中给出原因。
3. **全局代价（权重全部公开，直接显示在面板上）**：

   ```
   cost = 异常谱音数 × 10.0
        + 来源切换次数 × 3.0
        + Σ 切点两侧起音响度差(dB) × 1.0
        + Σ 切点两侧局部速度比之差 × 2.0
   ```

   权重常量集中在 `backend/app/config.py`（`SYNTH_W_*`），清单 `params`
   段原样携带。动态规划在**相同代价**下按“录音快照顺序（基线最前）→
   谱位升序”稳定取字典序最小方案，结果不随字典哈希顺序变化。
4. **钉住 / 禁用**：选源表中点击某个合格单元格 = **钉住**该谱位来源
   （再点取消，📌 标记）；点表头 = **禁用 / 启用**整次录音（删除线）。
   每次修改立即重新规划；钉住的来源在该谱位不合格时该谱位进入阻塞清单。
   **对已固化（built）任务施加任何约束都不会删除既有产物**：PUT 只更新
   规划，旧 WAV、清单、固化版本与试听 / 下载能力全部保留，状态行显示
   “已固化 + 规划阻塞 / 待重建 + 旧 WAV 已保留”。
5. **切点与渲染**：切点只落在后段首个谱音的**已对齐起音边界**
   （输出时间即基线该音起音），每段在相邻锚点间逐段线性时间映射
   （来源 Δt ÷ 基线 Δt = 变速比，尾区间按末段比值外推），切点处
   **20ms 线性交叉淡化**，确定性峰值归一化（只降不升），输出 22.05kHz
   单声道 PCM16 WAV。
6. **阻塞即阻止重建，但保留固化产物**：任一谱位没有合格来源时
   **当前规划**状态为 `blocked`，面板顶部红色清单逐位给出谱位坐标与
   原因（无合格来源 / 全部禁用 / 钉住来源不合格…），重建按钮禁用，
   `POST /rebuild` 返回 **422** 并携带逐位原因（不改动任何已固化数据）。
   若任务此前已 built，任务行 `status` 仍为 `built`、`plan_status` 为
   `blocked`，旧 WAV / 清单继续可试听、可下载（`build_preserved=true`）；
   从未固化过的任务行状态为 `blocked`、无产物可下载。
7. **显式重建与固化**：点 **⚙ 显式重建并导出 WAV** 才渲染并固化。
   约束改变（钉住 / 禁用）后任务出现 `rebuild_required` 标记，
   旧 WAV 照常可听；解除阻塞后**必须再次显式重建**：新 WAV 先写
   同目录临时文件、fsync 后 `os.replace` **原子替换**（渲染失败不留下
   半截文件），清单随之替换。清单 `frozen_sources` 记录每个来源的
   **对齐版本号与 WAV sha256**。之后来源复盘再怎么改，已固化 WAV
   都不变，只出现“过期”橙标；对比过期时 PUT 约束与 POST 重建一律
   返回 **409**，必须先显式刷新对比，再显式重建。
8. **试听 / 下载**：固化后出现内置播放器，以及 **⬇ 下载 WAV** 与
   **⬇ 下载确定性清单 JSON**。阻塞规划 / 待重建期间播放器仍播放**上次
   固化**的 WAV 并给出提示。清单含原始来源时间段、输出时间段、
   逐区间变速比、逐切点代价明细、固化版本 / 哈希；相同规划下 WAV 与
   清单字节级一致（键排序、固定精度、无时间戳 / 随机项）。

### 合成任务状态与文件生命周期

| 场景 | 行 `status` | `plan_status` | WAV / 清单 | 接口 |
|---|---|---|---|---|
| 新建（规划可导出） | `draft` | `draft` | 无 | POST 200 |
| 新建即阻塞 | `blocked` | `blocked` | 无 | POST 200；rebuild 422 |
| 显式重建成功 | `built` | `draft` | 原子写入 | rebuild 200 |
| **built 后改约束致阻塞** | **`built`（保持）** | `blocked` | **原样保留可试听下载** | PUT 200；rebuild **422** |
| built 后改约束（仍可导出） | `built` | `draft` | 旧文件保留，`rebuild_required=true` | PUT 200 |
| 解除阻塞（约束回到固化值） | `built` | `draft` | 旧文件保留 | PUT 200 |
| 解除阻塞后显式重建 | `built` | `draft` | **原子替换** WAV + 清单 | rebuild 200 |
| 来源变化 / 对比过期 | `built` + `stale=true` | — | 旧文件保留 | PUT / rebuild **409** |
| 删除任务 | — | — | WAV 文件一并删除 | DELETE 200 |

GET `/api/synthesis/{id}` 还返回：`build_preserved`（阻塞下旧产物是否
保留）、`rebuild_required`（约束或固化来源版本/哈希已变、须显式重建）、
`wav_available` / `wav_url` / `manifest_url`（试听下载能力是否可用）。

## 2d. 偏差练习处方与复测

入口：顶部第三个标签页 **“偏差练习处方”**（仍是 http://localhost:8000，
纯前端切换；接口前缀 `/api/prescriptions`）。也可以在单次复盘页点
**“＋ 用此乐曲开处方”**，或在打开的对比页点
**“＋ 用此对比赛处方”**（对比过期时按钮会被拒绝）。

1. **框选谱段与逐段规则**：用谱音下标（或点击展开谱面条“第 1 击设起点、
   第 2 击设终点”）框选若干**连续**谱段（按升序、不可重叠，最多 20 段），
   每段声明：
   * **必须消除的偏差类别**（至少一个）：`wrong_pitch` 错音、`missing`
     漏音、`extra` 多音、`onset_offset` 起音偏移、`duration_deviation`
     时值偏差；
   * **允许的最大起音误差**（秒，默认 `0.12`）与**最大时值比例误差**
     （`|实际/期望 − 1|`，默认 `0.20`）——复测时按处方阈值**现场重判**，
     可以比全局默认阈值更严；
   * **最多异常音数**（仅统计声明类别，默认 0）；
   * **是否禁止待确认**：勾选后段内存在未处置歧义/待确认即判**未通过**；
     不勾选则这类谱音只会让该段**不可判定**。
2. **只读固化（创建即冻结）**：提交（自动带 `request_id`）后，处方行冻结
   **乐谱指纹**（展开序列 + 原谱坐标的 sha256）、来源**对齐版本**
   （乐曲：该录音当前版本；对比：基线指纹 + 各成员只读快照版本）与全部规则。
   规则与固化内容之后不可编辑，只能作废或（来源过期时）重绑。
3. **关联同曲录音复测（准入分两条独立校验）**：下拉只列**谱指纹一致**的
   已分析录音，并为每个录音标注准入状态。提交后系统在**该录音当次已确认
   对齐版本**上，按处方谱段逐音、逐规则重算，并在复测记录中**当场固化**
   目标对齐版本、目标音频哈希、逐项结果与**所依据的来源固化版本**：
   * **通过 pass**：所有规则满足，且段内没有不可判定谱音；
   * **未通过 fail**：存在明确违反阈值/类别的规则；
   * **不可判定 undeterminable**：无明确失败，但存在未处置待确认（且处方
     未禁止）、用户已排除谱音或置信度 `< 0.50` 的谱音。

   每条规则都给出**实际值 / 阈值 / 是否满足 / 证据音符（谱音下标）/
   失败原因**；“证据音符明细”可展开到每个谱音的实际起音、Δ起音、时值比、
   音高偏差、置信度与观测下标；段内多音（额外音）单列并就近归入谱段。

   * **同曲新目标无需重绑**：即使该录音从未列入处方的来源固化成员（例如
     处方是从单支录音创建的），只要谱指纹一致且它有**当次已确认对齐**，
     就可以直接复测；复测时以它的当前版本为准并固化进复测记录。
4. **拒绝与过期（均为 409），绝不静默采用未确认结论**：
   * **来源过期 `source_stale`**：处方的来源固化成员中**任一个**的对齐
     版本 / 音频哈希 / 谱文件与固化时不一致（含被移出对比）——**无论复测
     目标是谁**都必须先**显式重绑**；响应体 `stale_members` 列出过期成员与
     原因。重绑原单曲来源即可解除，不需要把新目标加入来源；
   * **谱指纹不同 `fingerprint_mismatch`**：目标与处方不是同曲（或反复
     展开结果不同），拒绝复测；
   * **目标无已确认对齐 `no_confirmed_alignment`**：目标尚未完成分析或
     没有已确认对齐版本，拒绝复测；
   * **处方已作废 `prescription_voided`**。

   响应体带 `reason` 与具体版本号/指纹，前端按原因给出中文说明。
5. **来源过期 → 显式重绑，旧结果保留**：处方创建后来源对齐版本或音频哈希
   变化时，详情页出现橙色“来源已过期”横幅；必须点 **“🔗 显式重绑来源”**
   （对比来源须先在对比页显式刷新）才以最新已确认版本重新固化。重绑要求
   谱指纹一致；**所有历史复测原样保留**（包括旧目标版本、旧音频哈希与逐项
   结果），固化版本历史在时间线中追加一条；新复测记录新的来源版本号。
6. **状态机**：`created`（待复测）→ `retested`（有复测，可继续复测）→
   `voided`（终态：不能复测也不能重绑；历史保留）。不存在其他跃迁。
7. **`request_id` 幂等**：创建与复测都必须带 `request_id`；服务端把**首次
   响应**（含 200 与 409 拒绝，如来源过期/指纹不符）按 request_id 持久化，
   重复提交（含网络重试）直接回放同一处方/同一复测结果或同一拒绝，不会
   产生第二条记录、也不会改用新目标重新判定。同一 request_id 跨操作类型/
   跨处方使用返回 409。
8. **时间线与复测差异**：左侧时间线按时间合并 创建 / 显式重绑 / 各次复测
   （圆点颜色 = 通过/未通过/不可判定）/ 作废；右侧“复测差异”任选两次复测，
   按谱段 × 规则对比判定翻转（违反→满足 / 满足→违反）、实际值变化与证据
   谱音的新增/消除（“#3 新增、#6 消除”），以及不可判定谱音的增减。
9. **确定性**：复测结果 JSON（`GET /api/retests/{id}`）键排序、固定精度、
   无时间戳/随机项；相同规则 + 相同对齐版本结果字节级一致。

## 2e. 偏差片段练习谱

入口：顶部第四个标签页 **“偏差片段练习谱”**（仍是 http://localhost:8000，
纯前端切换；接口前缀 `/api/practice-scores`，创建挂在
`/api/pieces/{id}/practice-scores`）。最方便的入口是先在“单次复盘”页打开
一支已分析的录音，再点 **“＋ 生成偏差片段练习谱”**。

**启动与版本操作**：`docker compose up --build` 后浏览器访问
<http://localhost:8000>，第四个标签页即练习谱。打开任一练习谱：

* 顶部状态行显示**当前版本**（如 `v2（共 3 版）`）；
* **版本历史**面板按新版本在前列出全部成功生成：`当前` 徽标为当前版本，
  橙色`过期`表示该版本固化来源已变化；每行可直接 **⬇ MusicXML / ⬇ 清单
  JSON** 下载那一版，点 **查看该版本练习顺序** 展开该版逐轮坐标与 BPM；
* **↻ 显式重建**通过校验后追加新版本并把当前版本切到新稿，确认框会明示
  “失败不新增/不改写任何版本”；
* **删除练习谱**会删除全部版本文件。

1. **框选连续片段（展开小节 × 反复轮次）**：编辑器按反复**展开后**的顺序列出
   整小节，反复小节标注**第 N 次演奏**。每个片段由“起始小节 / 结束小节
   （含轮次）”界定，必须沿展开顺序连续；片段之间**不得重叠**，片段本身的
   先后顺序就是**练习顺序**（最多 20 段）。可在小节条上点击：第 1 击设起点、
   第 2 击设终点。
2. **逐段循环与速度**：每段设置
   * **循环次数** `loops`（1–99）；
   * **起始速度** `start_tempo_bpm`（20–300 BPM，四分音符为拍）；
   * **逐轮增速** `tempo_increment_bpm`（0–100 BPM/轮）与方向
     `up`（逐轮增速，默认）/ `same`（恒速）/ `down`（逐轮减速）；
   编辑器实时给出“第 1 轮 → 末轮”速度，末轮速度超出允许范围会阻止生成。
3. **逐位准入校验，阻止生成（422）**：提交（或编辑器内实时预览）时逐谱位检查，
   每个片段都必须满足：
   * **每段至少包含一个已确认偏差音**：错音 / 漏音，或置信度达标的起音偏移 /
     时值偏差（段内就近归入的已确认多音也算）；
   * 段内不得存在 **待确认**（未处置多声/无声歧义，含其阴影谱位）、
     **用户已排除**或**置信度低于 `0.50`**
     （`config.PRACTICE_MIN_CONFIDENCE`）的谱位。

   任一不满足，响应 `422 reason=blocked_positions`，`blockers` 逐位给出
   片段号、谱音下标、原谱坐标与原因（`pending_confirmation` / `excluded` /
   `low_confidence` / `no_confirmed_deviation`），**不生成任何文件**；
   界面在对应片段下红色逐位列出原因。
4. **整小节提取与练习谱生成**：系统从**原 MusicXML** 按反复展开后的演奏轮次
   提取对应**整小节**（music21 展开反复；一/二房子等同小节号不同内容按反复
   顺序对回，签名不符会在清单 `expansion_warnings` 提示），并：
   * **保留**音高、时值（含附点等）、**休止**、拍号、调号、谱号（段内拍号/
     调号变化同样保留，每轮开头统一补齐片段起点的生效属性）；
   * 片段内部的延音线（tie）与连音线（slur）**原样保留**；
   * **跨片段（以及跨循环轮）的连音在片段边界截断**：删除悬空的 tie/slur 端，
     在对应小节插入“〔截断标记〕…”文字，清单 `truncated_spanners` 逐处记录
     片段/轮次/小节/进出端/音名，**保证输出谱没有悬空连音**；
   * 剥离原反复记号/房子/导航与原有速度标记，每个片段按用户选定顺序、
     按轮复制展开，**每轮开头**用排练记号 + 文字 + `<metronome>`/`<sound>`
     注明“片段 k · 第 i/n 轮”、**原谱坐标**（小节与第 N 次演奏）与该轮
     **BPM 速度**；输出小节从 1 连续编号，末尾常规终止线。
5. **只读版本固化与过期（历史稿始终可下载）**：创建成功即固化为 **v1**。
   下载的 MusicXML `<identification><miscellany>` 与确定性清单 JSON 一并固化：
   **版本号、来源谱文件 sha256、创建/重建时的对齐版本、生成参数（阈值/速度
   规则/算法版本）**，以及生成文件自身 sha256（相同片段 + 相同来源字节级一致，
   先写版本独立文件 `practice_{id}_v{n}.musicxml` 的同目录临时文件、fsync 后
   `os.replace` 原子落盘）。之后来源谱哈希或对齐版本变化，详情与列表只在
   **当前版本**上出现橙色**过期**标记（`score_changed` /
   `alignment_version_changed`）：**当前版本与全部历史版本的 MusicXML /
   清单照常下载**，系统绝不静默重生成、绝不覆盖任何旧稿。
6. **显式重建 = 追加新版本**：点 **“↻ 显式重建”**才按当前来源重新逐位校验、
   提取并**追加一个独立版本**（版本号 +1），成功后把任务的**当前版本指针**
   原子切换到新稿，旧版本文件、固化清单与数据库行全部保留；若来源变化导致
   片段里出现待确认/排除/低置信谱位，重建返回 **422 逐位原因**，或渲染 /
   落盘出错——这些都发生在写入版本之前，因此**不新增、不改写任何版本**，
   当前版本指针不动，**已有过期稿仍可下载**。解除阻塞后再次显式重建才生成
   新版本，新版本固化的哈希 / 对齐版本随之更新。
7. **版本历史与逐版本下载**：详情页“版本历史”按版本号**降序**列出每次
   成功生成（当前版本带标记），逐版本显示生成时间、固化的对齐版本、练习谱
   sha256 与过期标记，可展开查看该版本的逐轮练习顺序 / 原谱坐标 / BPM，
   并分别下载该版本的 MusicXML 与确定性清单。删除练习谱会一并删除
   **全部版本**的固化文件与版本行。

### 练习谱任务与版本生命周期

| 场景 | 行 `status` | 当前版本 | 版本文件 | 接口 |
|---|---|---|---|---|
| 创建（校验通过） | `built` | v1 | 原子生成 `..._v1` | POST 200 |
| 含阻止谱位/无偏差音 | — | 无 | **不生成** | POST **422** 逐位原因 |
| 来源谱/对齐版本变化 | `built` | 旧版本标 `stale` | **当前+历史版本均可下载** | GET 标过期 |
| 过期后显式重建仍被阻塞 | `built` | **指针不变** | **不新增版本，旧稿保留** | rebuild **422** |
| 重建渲染/落盘出错 | `built` | **指针不变** | 不留半截/临时文件 | rebuild 500 |
| 解除阻塞后显式重建成功 | `built` | **追加并切换到 v(n+1)** | **新文件独立落盘，v1..vn 全保留** | rebuild 200 |
| 查看版本历史 / 下载旧版本 | — | — | 只读 | GET versions / versions/{v}/... |
| 删除任务 | — | — | **全部版本文件 + 版本行清理** | DELETE 200 |

GET `/api/practice-scores/{id}` 返回：`status`、`current_version`、
`version_count`、`versions`（版本历史摘要：版本号 / 是否当前 / 过期原因 /
固化对齐版本 / 生成文件哈希 / 生成时间 / 下载入口）、`stale` /
`stale_reasons`（针对当前版本）、`segments`（片段参数）、`practice_order`
（当前版本的每轮片段/轮次/原谱坐标/BPM/输出小节/该轮截断明细）、
`truncated_spanner_count`、`frozen`（当前版本号、来源谱哈希、固化与当前
对齐版本、生成文件哈希）以及指向**当前版本**的 `musicxml_url` /
`manifest_url`。历史版本通过 `/versions` 与 `/versions/{version}/...`
访问；不带版本的 `/musicxml`、`/manifest` 始终等价于当前版本。

## 2f. 谱面修订迁移

入口：顶部第五个标签页 **“谱面修订迁移”**（仍是 http://localhost:8000，
纯前端切换；接口前缀 `/api/revisions`，上传挂在
`/api/pieces/{id}/revisions`）。最方便的入口是先在“单次复盘”页打开一支
已分析录音，再点 **“＋ 谱面修订迁移”**。

1. **上传修订版单声部谱**：选择当前录音的 MusicXML 与修订版
   `.xml/.musicxml/.mxl`。上传时先做**多声部静态扫描**——检测到多 part、
   小节内多 voice 或任意 `<chord/>` 直接 **422 `polyphony_ambiguous`**，
   不生成预览；随后用 music21 对两侧谱面都 `expandRepeats()`。
2. **确定性匹配（按原谱坐标 + 内容）**：对展开后的两侧谱音做一次全局单调
   序列对齐（公开代价，报告 `params` 段完整携带）：

   | 分类 | 判据 | 代价 |
   |---|---|---|
   | `kept` 保留 | （小节, 反复轮次, 拍位）一致且音高、时值一致 | 0 |
   | `modified` 修改 | 同谱位但音高或时值变化 | `0.4` |
   | `moved` 移动 | 音高+时值完全一致但谱位不同 | `0.3×单位跨越 + 0.02×拍位差` |
   | `deleted` 删除 | 旧谱音在全局对齐中无对应 | `1.0` |
   | `added` 新增 | 新谱音在全局对齐中无对应 | `1.0` |
   | `unmatched` 无法匹配 | 谱位键重复 / 缺原谱坐标等结构性冲突 | — |

   等代价时回溯按“配对→删→增”固定优先级；某个配对与删除/新增替代的
   **次优间隔为 0** 即移动目标非唯一，登记 `ambiguous_move`。修改/移动/
   删除/新增由同一个 DP 一次性给出，**不会被两阶段贪心误判**（例如前面
   插入音符导致的整体顺移会正确归为移动而不是逐音修改）。
3. **冲突阻止提交（422），预览照做并逐项列出**：
   * `polyphony_ambiguous`：修订谱多声部 / 和弦（上传阶段即拒绝）；
   * `duplicate_position`：同一（小节/轮次/拍位）有多个谱音，匹配键不唯一；
   * `missing_coordinate`：谱音缺原谱小节或拍位坐标；
   * `ambiguous_move`：等代价移动配对，迁移目标非唯一。

   含冲突的预览可以保存查看（`has_blockers=true`、`can_commit=false`），
   但**确认按钮禁用 / 接口 422**；可“放弃预览”删除后重新上传。
4. **迁移预览（历史产物逐项继承判定）**：

   | 历史产物 | 可继承 `inheritable` | 需复核 `review` | 失效 `invalid` |
   |---|---|---|---|
   | 锚点 `exclude_score` | 谱位保留：自动预置到新入口 | 谱位移动/修改 | 谱位删除/无法匹配 |
   | 锚点 `lock`/`force_lock` | — | 一律需复核（绑定旧录音起音，须用新录音重建） | — |
   | 锚点 `exclude_obs` | — | — | 一律失效（纯音频观测排除） |
   | 对齐快照 | — | — | 一律失效（固化的是旧指纹+旧音频结论，只读保留） |
   | 未过期对比 | — | 可在新入口分析后显式重建同成员对比 | 已过期对比 |
   | 处方 | 规则段全部落在保留谱位：生成接续模板 | 段内含移动/修改：按新下标拆分映射 | 段内谱位删除/无法匹配；已作废处方 |
   | 练习谱片段 | 展开单位全部保留：生成接续模板 | 单位内有移动/修改或映射后不连续 | 单位消失/无法对回 |

   每个判定都带中文**原因**（如“谱位为移动：请在新录音复盘时复核是否
   仍需排除”“快照固化的是旧谱指纹与旧录音的逐音结论”）。
5. **确认提交（禁止静默改写历史）**：点 **✓ 确认迁移**（自动/手填
   `request_id`，幂等回放首次响应，含 422）。系统再次核对：修订谱 sha256、
   来源谱 sha256、来源对齐版本与预览固化时一致——**预览后来源变化**
   （重新对齐 / 谱文件变化）返回 422 `source_*_changed_since_preview`，
   必须重新上传生成预览。通过后：
   * 创建新的 `score_revisions` 行（`status=committed`）与**新复盘入口
     piece**（复制修订谱为 `{new_id}.xml`、写入展开谱音，状态 `created`，
     尚无音频），并把**可继承的排除锚点**预置到新入口（其余锚点只读留旧
     入口）；接续所需的处方/练习谱映射模板随修订记录固化；
   * **旧录音与全部历史产物原样只读**：旧对齐版本、对比快照、处方及复测、
     练习谱全部版本均不改写；已确认修订记录不可删除。
6. **后续录音与一键接续**：在修订详情页向新入口上传 WAV（后台分析并自动
   首次对齐，轮询 `/api/jobs/{new_piece_id}`）。分析完成后
   `/api/pieces/{new}/revision-context` 列出可接续模板（未分析完成时
   `ready=false`）；点 **一键接续**显式创建**全新**处方 / 练习谱——处方
   按新下标连续区间（不连续映射自动拆段）复制原规则，练习谱按新
   （measure+occurrence）单位复制片段参数并**重新逐位准入**：新录音该段
   无已确认偏差音 / 含待确认等时返回 **422**，不生成新练习谱。
7. **只读与导出**：旧记录只读可下载；修订详情提供
   **⬇ 修订版 MusicXML** 与 **⬇ 确定性迁移报告 JSON**（两侧哈希、固化
   对齐版本、公开代价参数、逐谱位匹配与原因、逐项继承判定；键排序、
   固定精度、无时间戳 / 随机项，相同输入字节级一致）。

### 修订记录生命周期

| 场景 | 记录状态 | 新入口 | 接口 |
|---|---|---|---|
| 上传修订谱（无冲突） | `preview`（可提交） | 无 | POST 200 |
| 上传修订谱（含冲突/多声部） | 多声部直接拒绝；其余 `preview` + `has_blockers` | 无 | 上传 422 / 提交 422 |
| 放弃预览 | 记录与修订文件删除 | — | DELETE 200 |
| 确认提交（request_id 幂等） | `committed`（只读不可删） | 创建 piece + 预置可继承锚点 | commit 200 |
| 预览后来源谱/对齐版本变化 | 仍为 `preview` | 阻止提交 | commit **422** |
| 已提交重复确认 | — | 回放首次响应（同 new_piece_id） | commit 200/409 |
| 新入口上传录音 | `committed` | 后台分析→`analyzed` | POST audio 200 |
| 一键接续处方 | `committed` | 生成**全新**处方 | carryover 200 |
| 接续练习谱但逐位准入不通过 | `committed` | **不生成** | carryover **422** |

## 3. 判定分类

| 状态 | 含义 | 主要依据（basis 示例） |
|---|---|---|
| `correct` | 配对且音高/时间在阈值内 | `pitch_delta=0.0semitones`、`dp_margin=...` |
| `wrong`（错音） | 配对但基频偏差 ≥ 1 半音 | `pitch_delta=…semitones` |
| `missing`（漏音） | DP 路径上该乐谱音无观测 | `no_observation_on_dp_path`，给出预测起音 |
| `extra`（多音） | 稳定观测在 DP 路径上无对应乐谱音 | `no_score_note_on_dp_path` |
| `onset_offset` 标签 | 起音相对*局部平滑速度基线*偏差 ≥ 0.12s | `onset_offset=…s` |
| `duration_deviation` 标签 | 实际/期望时长比 <0.8 或 >1.2（且绝对差 ≥0.08s） | `duration_ratio=…` |
| `pending`（待确认） | 观测为多声部歧义或无声片段 | `polyphony_ambiguous` / `silent_segment`、`no_forced_match` |
| `excluded` | 用户显式排除 | `user_excluded_*` |

歧义规则：段内有声帧比例 < 0.25 → `silent`；双峰帧比例 > 0.25 → `poly`。
置信度由“最优路径 vs 次优替代”的 DP 代价间隔映射（锁定锚点恒为 0.99）。

所有阈值集中在 `backend/app/config.py`，导出 JSON 的 `params` 段完整携带，
保证判定可复现、可审计。

## 4. 算法说明

1. **反复展开**：`music21` 的 `part.expandRepeats()` 展开 D.C./D.S./反复小节
   与结尾，得到展开后四分音符坐标 `beat`；同时保留
   `measure / beat_in_measure / occurrence` 原谱坐标。和弦只取最高音并告警。
2. **音频分析**（librosa，22.05kHz 单声道）：`onset_strength + peak_pick`
   检测起音（合并 60ms 内过近起音）；每段 `pyin` 基频 + 频谱第二峰占比，
   输出 `stable / poly / silent` 三态与各自置信指标；另输出 1000 点波形
   峰供前端绘制。
3. **两遍单调 DP 对齐**：
   * 网格转移 = `match`（对角）/ `delete`（漏音）/ `insert`（多音），
     天然允许漏音、额外音；
   * **Pass A** 粗配（音高 + 低权重时间残差）收集配对点，用
     **Theil–Sen 稳健回归**拟合片段局部速度 `t = α·beat + β`，容许局部
     速度变化；锁把网格切成独立片段，各片段独立拟合；
   * **Pass B** 细配加入全权重起音残差（设上限，避免速度漂移被重罚）。
     音高相差 > 6 半音**禁止自动配对**（宁可“漏+多”也不强配错音）；
     `poly/silent` 观测只能以低代价暂挂，进待确认。
   * 每个 match 记录对角方案相对最优非对角方案的代价间隔 → 置信度。
4. **增量重算**：Pass B 片段结果以
   `(边界, 排除集合, 片段局部α/β)` 为键缓存；增删锚点后未受影响片段直接
   命中缓存，只重算真正变化的片段（顶部显示命中/重算数）。
5. **起音/时值判定**：对相邻匹配的局部速度做 3 点中值平滑作为期望基线
   （吸收渐进速度变化，单点唱早/晚仍暴露）；期望时值按 `dur_q × α`。

## 已知边界

* 仅承诺**单声部**旋律：多 part / 和弦取最高音并告警，相关片段建议人工确认。
* 音频为单进程后台分析；如需并发可在 compose 中改为多 worker +
  外部任务队列（锚点状态全部落库，可无缝迁移）。
* 阈值针对自然声学乐器/人声设定；极端音色可在 `config.py` 统一调整后，
  导出 JSON 中的 `params` 会体现差异。
